# RAG Knowledge Assistant

Прототип конвейера для построения RAG-ассистентов. Демонстрационная инстанция — голосовая энциклопедия динозавров для ребёнка.

## Контекст и цель проекта

Это пет-проект, созданный для изучения возможностей применения ИИ в роли бизнес-аналитика.

**Цель:** проверить гипотезу — может ли бизнес-аналитик, используя ИИ как инструмент разработки, быстро создать работающий прототип на основе своих продуктовых требований.

**Моя роль:** продуктовая постановка задачи, описание сценариев использования, определение критериев качества ответа, валидация результатов, сгенерированных ИИ.

**Роль ИИ:** написание кода (Python), генерация текстов README, предложение метрик оценки (Accuracy@1/@3) как стандартных для RAG-поиска.

## Архитектура конвейера (по спецификации)

    [PDF/текст] → [Загрузка в локальное админ-приложение] → [Эмбеддинг] → [Vector DB]
                                                                              ↓
    [Голосовой запрос] → [STT] → [RAG-поиск] → [LLM с ролью] → [TTS] → [Ответ]

### Ключевые компоненты (текущий стек — Яндекс)

1. **Загрузка знаний:** локальное админ-приложение на CustomTkinter
2. **Эмбеддинг и генерация:** YandexGPT с настраиваемым chunk_size
3. **Vector DB:** Qdrant (локально) для поиска по косинусному сходству
4. **RAG-поиск:** Top-K retrieval с reranking по relevance score
5. **Роль ответа:** системный промпт, задающий тон и стиль
6. **Голосовой ввод/вывод:** SpeechKit (STT/TTS)

## Статус проекта

**Демо:** на стопе. Проект был развёрнут на Яндекс Cloud; после инцидента в дата-центрах Яндекса серверы стали недоступны, и публичное демо перестало работать.

**План:** миграция на Gigachat (эмбеддинги и генерация ответов). Миграция на этапе изучения документации и планирования, ещё не выполнена. Поэтому в коде и в инструкциях ниже фигурирует Яндекс-стек — это текущее состояние репозитория, а не желаемое.

## Метрики качества поиска

ИИ предложил Accuracy@1 и Accuracy@3 как стандартные метрики для оценки RAG-поиска. Я валидировала их вручную на небольшом тестовом датасете вопросов по энциклопедии динозавров:

| Метрика | Значение | Описание |
|---------|----------|----------|
| **Accuracy@1** | 78% | Правильный ответ в первом результате поиска |
| **Accuracy@3** | 92% | Правильный ответ в топ-3 результатах |
| **Hallucination rate** | ~8% | Ответы, не основанные на базе знаний |

Цифры ориентировочные, сняты до остановки демо. Для production-оценки нужны более строгие методики (NDCG, MRR, человеческая разметка).

## Известные ограничения и дыры в тестировании

**Проблема STT-каскада (указана Павлом Нестерчук (Beckend-инженер) в обсуждении):** в текущей версии нет отдельной проверки того, правильно ли распознаватель речи записал то, что ему сказали. Криво распознанный текст едет дальше по цепочке, и итоговая цифра результата получается неверной — непонятно, ошиблись «уши» (SpeechKit) или поиск по базе.

**Как буду закрывать:** добавлю в тесты пары «что наговорили / что распознали», чтобы разделять ошибки распознавания и ошибки поиска/генерации. Заложу эту проверку в тесты сразу, чтобы после переноса на Gigachat было на что смотреть.

**Потеря контекста при чанкинге:** при нарезке PDF на фрагменты заголовки разделов и условия применения могут оставаться в соседних чанках. Тогда поиск находит похожий фрагмент, но без контекста, и модель отвечает неправильно. Это не ошибка модели, а ошибка подготовки данных.

**Как буду закрывать:** при миграции на Gigachat пересмотрю стратегию чанкинга — сохранять заголовок раздела в каждом фрагменте, не отрывать строки таблиц от названий столбцов, проверять поиск по словам пользователя, а не только по терминам автора.

**Другие ограничения:**
- Нет разделения ошибок эмбеддинга и ошибок генерации
- Тестовый датасет маленький и не размечен независимо
- Нет оценки качества на длинных диалогах (только одиночные вопросы)

## Что моё, что ИИ

### Моё (бизнес-анализ и продуктовая часть):
- Формулировка требований: «ассистент должен отвечать дружелюбным тоном только на основе загруженной базы знаний»
- Определение критериев успеха: первый ответ должен быть точным (отсюда фокус на Accuracy@1)
- Валидация: ручное тестирование ответов ассистента на контрольных вопросах для проверки отсутствия галлюцинаций
- Описание процесса и сценариев использования
- Идея проверки пар «наговорили / распознали» для разделения ошибок STT и RAG

### ИИ (техническая реализация):
- Написание Python-скриптов для конвейера
- Генерация текста README
- Предложение метрик Accuracy@1 и Accuracy@3 как стандартных для оценки RAG-поиска

## Локальный запуск (текущий стек — Яндекс)

    git clone https://github.com/Kris-Tsilik/rag-knowledge-assistant.git
    cd rag-knowledge-assistant
    pip install -r requirements.txt

    # Запустить админ-приложение для загрузки PDF
    python admin_app.py

    # Запустить голосового ассистента
    python main.py

**Требования:** Python 3.9+, микрофон, колонки, API-ключ YandexGPT / SpeechKit.
